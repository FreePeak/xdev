Session Design & Lifecycle Comparison

Claude Code

Claude Code is an agentic coding assistant in the terminal. Sessions are stored locally as append-only JSONL transcripts under ~/.claude/projects/, enabling rewind/resume/fork. Each new session starts with a fresh context window.

Lifecycle phases (hooks)

  • Setup — one-time project init/maintenance in headless mode (--init/--maintenance).
  • SessionStart — fires on startup/resume/clear/compact/fork; can inject context; matchers: startup, resume, clear, compact, fork.
  • InstructionsLoaded — when CLAUDE.md/rules are read into context.
  • ConfigChange / CwdChanged — mid-session config or directory changes.
  • PreCompact / PostCompact — before/after context compaction (manual or auto); PostCompact carries compact_summary.
  • SessionEnd — on exit with reason (clear, resume, logout, prompt_input_exit, other).
  • Tool lifecycle: PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied.
  • Subagent lifecycle: SubagentStart/SubagentStop; agent coordination: TeammateIdle, TaskCreated, TaskCompleted.

Session operations

  • Resume (--resume/--continue): rebuilds conversation by replaying transcript; session-scoped permissions are NOT carried (safety-conservative).
  • Fork: new session from existing one (--fork-session), inherits grants in-process.
  • Compaction: read-time projection over full history (non-destructive); transcript stays append-only.
  • Subagents: subordinate workers within one session, own context window, possibly different model.

OpenCode

OpenCode (SST) uses a client-server architecture: an HTTP server holds state, TUI/IDE clients connect. Sessions, messages, files, providers, tools, agents exposed via API. Stored in SQLite (modernc). Messages are arrays of typed Part objects.

Session model

  • Session.fork() — copies conversation history up to a specified message, creating a child session with its own ID, lineage via parentID. Original unaffected.
  • Parent-child relationships — subagent sessions spawned by primary agent, own context window, own tools/system prompt, possibly different model.
  • Instruction state — AGENTS.md/CLAUDE.md loaded per session; nested files loaded nearest-first; moving a session retains instruction state; revert clears & reloads.
  • Compaction — experimental.session.compacting hook; session.idle hook.
  • Events over SSE — persisted message parts emit events on a shared bus exposed over HTTP/SSE; real-time updates to any client.
  • Permission system — workflow safeguard; server mode needs OPENCODE_SERVER_PASSWORD.

Two-tier agents

  • Primary agents + subagents (Task tool spawns subagent session).
  • Plan mode disables edits; suggests implementation.

oh-my-pi (omp)

omp is a TypeScript+Rust terminal coding agent (fork of Pi) with 40+ providers, subagent orchestration across worktrees, hash-anchored edits, LSP/DAP integration. Sessions stored on disk under ~/.omp/agent/sessions (or PI_CODING_AGENT_DIR).

Session lifecycle events (hooks)

  • session_start — initial session load.
  • session_switch — reason (new/resume/fork), previousSessionFile; after a session becomes active.
  • session_branch — after branching.
  • session_before_switch — cancelable (cancel:true stops switch).
  • session_before_branch — cancelable; skipConversationRestore option.
  • session_before_compact — cancel or provide custom CompactionResult; first cancellation wins.
  • session.compacting — customize prompt/context/preserveData for default compaction.
  • session_compact — post-compaction notification with compactionEntry.
  • session_before_tree / session_tree — tree navigation.

Session operations

  • /new fresh session, /resume picker, --continue/-c last session, --no-session ephemeral.
  • /tree in-place branch nav, /branch /fork /clone copy/branch sessions.
  • /compact summarize old context; compaction persists read/modified files.
  • Subagents — fork-based: detached pi processes, fork main conversation (full context inherited), child session visible in /resume.
  • Collab — shared live sessions via relay; resume/fork across devices.
  • Memory — Hindsight-backed: autoRecall/autoRetain, retainMode full-session/last-turn, per-project-tagged scoping.
  • Model fallback — retries and moves down chain on failure; switches back when primary available; advisor role reviews completed turns.

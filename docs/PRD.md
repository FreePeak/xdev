# xdev — Product Requirements Document (lightweight Go coding agent)

**Product:** xdev · **Repo:** `FreePeak/xdev` · **Module:** `github.com/FreePeak/xdev` · **Binary:** `xdev` · **Data dir:** `~/.xdev/agent/`

Derived from the [omp/pi Go-rebuild architecture research](research/2026-09-09-omp-pi-architecture-go-rebuild.md) (2026-09-09). That research's proposed codename `adze` is **superseded by the repo name `xdev`**: every module path, binary name, and data dir below uses the product name. The session format stays compatible with omp's.

## 1. Product goals & non-goals

### Goals

1. **Single static CGO-free Go binary.** Cross-compiles to all six platforms omp supports, ~22 MB dev / ~29 MB installed with the pure-Go SQLite (mnemopi) memory backend linked in — measured 2026-09-12; the backend is a build-time choice, so a build without it keeps the original ~15 MB footprint (amended goal, see M15 row) — instant startup, no runtime install (research IV.0.2, Part V). **2026-09-13 fx cross-check:** neither the size nor the startup claim is enforced by anything. fx gates the same promises with numbers — 2 ms mean startup per command on one authoritative Linux runner, a 52,429-byte per-PR base-vs-head *delta* warning, and a 7.800 MiB release ceiling with 0.250 MiB reserved headroom. Enforcement is #118 (time) and #119 (size delta + ship gate + leak audit); the measurements above stay manual until those land.
2. **Hard <100 MB RSS budget.** Realistic working target 30–70 MB; worst case must stay under 100 MB — roughly 3–8× lighter than a JS-runtime harness. Achieved by having no JS runtime, windowing the in-memory session to the post-boundary tail, bounding every queue, streaming tool output through fixed-size sinks, and keeping the terminal as the scrollback archive (research Parts III, IV.1).
3. **Port the proven pi/omp data model, not the code.** The JSONL session tree (append-only + mutable leaf pointer), the unified `AssistantMessageEvent` stream contract, context reconstruction, compaction, the OutputSink, and the frame-plan TUI are ported with identical semantics and — where possible — identical entry names, for interop with existing session tooling (research IV.0.1).
4. **pi's minimal philosophy.** <1,000-token system prompt including tool descriptions; exactly four core tools (`read`, `write`, `edit`, `bash`); YOLO by default — no permission theater; containment belongs to external sandboxing. (Primary-source check 2026-09-09: pi v0.85 actually ships 8 built-ins — `read`, `write`, `edit`, `bash`, `powershell`, `grep`, `find`, `ls` — with a measured ~460–510-token prompt and MCP only via the `pi-mcp-adapter` extension; xdev keeps the four-core-tool surface and ships grep/find/ls as rg/fd shell-outs, docs/research/parity-pi-internals.md.)
5. **Extensions are processes, not in-process code.** Never load foreign code in-process; extensions are executables speaking JSONL on stdio with per-event timeout + SIGKILL (research IV.0.4, IV.8).
6. **Bounded everything.** Queues, buffers, session windows, and output sinks have hard limits; backpressure is a feature, not a bug (research IV.0.5).
7. **Inspectable sessions.** Fully documented, post-processable JSONL; the harness gives the user full control and inspection of what enters the model context (research I.2.5).

### Non-goals

- No JS/Bun runtime, no in-process plugin VM, no Rust N-API natives.
- No built-in permission/security system: YOLO by default; sandboxing documented externally (container/seatbelt/bubblewrap recipes, like pi). **2026-09-13 fx cross-check:** fx ships no OS sandbox either — searched, zero mechanisms, and its `sandbox` config key is proven inert (`config_runtime.zig:3141`) — so the non-goal holds. Two refinements are adopted anyway because they cost no sandbox and no permission theater: an *opt-in* bounded second-model approval tier (#117, §5.2) and a static-grammar read-only allowlist that auto-runs in a **3-variable scrubbed environment** (#114).
- No `stats.db`-scale sidecar accumulation (77 MB on the reference machine) — a tiny rollup table only.
- ~~No marketplace~~ → **Deferred to M15** (2026-09-11 full-parity directive: user wants all omp features; Go port over subprocess extensions, no bun — issue #53/#22).
- No tree-sitter embedding (CGO + memory); AST work shells out to the `ast-grep` binary when present.
- No in-tree Git library; shell out to `git` (no go-git for v1).
- No built-in LSP server management beyond opt-in-lazy launch: `gopls`/`rust-analyzer` start only when the `lsp` tool is used (omp's `lsp.lazy` default, research IV.10).
- ~~No desktop control (`computer`), full DAP debugging, `security_scan`, `tts`, `generate_image`~~ → **Deferred to M15** (2026-09-11 full-parity directive; per-OS Go backends / adapter-based DAP / scanner shell-outs designed per issue #65–#69).
- ~~No embedded local tiny models~~ → **Deferred to M15 as a decision issue** (#70): ONNX/MLX in Go breaks CGO-free or the memory budget; ship/record a decision, never silently.
- ~~No omp ecosystem services~~ → **Deferred to M15** (#63, #71, #72): Go services/equivalents per issue; the tiny-stats-rollup stance inside the agent binary is unchanged.
- ~~No `sharpshooter` memory backend~~ → **Deferred to M15** (#73) — friction-gated decision files behind the memory backend seam.

## 2. Scope

### In scope

- **Session core** — JSONL tree store: `EntryBase`/`Entry` union, fixed-width 256-byte title slot, append-only leaf-pointer tree, `buildContext` reconstruction, sha256 blob store, compaction (thresholds + overflow/incomplete recovery + context promotion), listing via 4 KiB prefix reads + stat-keyed cache, durability model (per-entry write + flush, optional strict fsync, latched errors, atomic stage-then-rename rewrites, fail-closed on indeterminate writes; **no foreign-writer length guard, no truncate rollback, no unfinished-turn discard at open** — #122).
- **Provider layer** — four wire adapters (Anthropic Messages, OpenAI Completions, OpenAI Responses, Google GenAI) hand-rolled over one shared SSE reader; unified `AssistantMessageEvent` contract; 256-byte partial-JSON throttle with relaxed repair parser; first-progress + idle watchdogs; model-host preconnect; bounded 1,024-event queue with delta coalescing; stop-reason maps + per-provider quirk tables; classified-error taxonomy (Flag bitmask + retriable kinds + overflow regexes, omp-context-resilience §3); failed-request dumps to disk; stalled-stream partial tool-call stubs are never executed (hermes pattern).
- **Agent loop** — one goroutine per turn; bounded tool worker pool (~4–8); steering channels (`steer`/`followUp`/`aside`, queued messages preserved, never discarded); persistence on `message_end` only; layered cancellation via `context.Context` chains; `todo` tool (9-op table, 5 statuses with `blocked`+`reason`, phased init) + TodoTracker loop engine (stop-time reminders max 3, mid-run nudge 12 mutations / 2 per cycle, blocked excluded) ported from omp v18; out-of-band user steering markers appended to tool results; `<untrusted_tool_result>` wrapping for web/browser/MCP output; per-result/per-turn tool-output budgets with disk spill (omp-todos-internals.md, hermes-internals.md).
- **TUI** — tcell + omp frame-plan port: `TerminalFramePlan { history?, viewport }`, active/settled/committed block states, history retirement batches, DSR-anchor resize recovery, alt-buffer overlays; pi-tui editor feature list (path completion — directory-scoped, never a repo walk: see §3's editor row, bracketed paste, multi-line, IME-safe cursor tail).
- **Tools** — `read`/`write`/`edit`/`bash` exactly per pi's input schemas; omp hashline edit UX (`PUT N.=M:`, `MV`, `CUT`, `REM`) + line-numbered snapshots; one `edit` tool carrying the hashline grammar (replace/patch/apply_patch/sloppy are NOT implemented — schema drift is **#267**); OutputSink fixed 32 KiB head + 32 KiB tail windows with omp's truncation marker as the record (**no artifact spill — the middle bytes are discarded**, #115); bash env-hardening list; tier approvals (read-only/write/exec) + `bash.patterns` with conservative compound-command combination; grep/glob/find/ls via rg/fd shell-outs under omp's caps; file-freshness (modified-since-read) rejection; optional backgrounded bash; hidden tools (`yield`/`goal`/`think`) mounted behind activity gates (parity-omp-internals.md).
- **RPC** — JSONL-over-stdio embedder contract: `ready` frame advertising protocol versions + frame limits (1 MiB; v2 chunked reassembly to 64 MiB); id-correlated inbound commands (prompt/steer/follow_up/abort/new_session/state/set_model/…); outbound responses, session/agent events, extension-UI dialogs, host-tool calls, host-URI requests, subagent frames; headless/print modes share the same session core with no UI context.
- **MCP client** — official Go SDK (`github.com/modelcontextprotocol/go-sdk`), stdio/HTTP transports, `list_changed` notifications, per-server enable/disable, tool filtering (e.g. browser-automation servers filtered when a built-in browser exists). MCP stays optional — pi ships without it for a reason (context poisoning; CLI tools beat MCP when equivalents exist).
- **Ext subprocess protocol** — extension = any executable speaking JSONL on stdio: capability handshake (tools, commands, event subscriptions, renderers as declarative specs) → event frames (`tool_call` may block/revise fail-closed; `tool_result` may patch) → runtime action requests (steer/followUp/aside, register provider). Per-event timeout + SIGKILL.
- **Subagents** — same session core with restricted tool sets (no ambient MCP/extensions/LSP), structured `outputSchema` (permissive/strict), a `yield` tool, artifact handoff; child = same binary in `print`/`rpc` mode or in-process goroutine sessions with their own `SessionStore`; fork (context-inheriting) vs fresh agent types; stall detection with retry escalation; subagent JSONL + meta.json persistence with orphan auto-resume (claude-code-internals.md).
- **Model resolution, providers, auth & config layering** — `defaultModel` plus an inline `:effort` suffix (the `modelRoles` alias table is gone); per-provider `models.yml` (baseUrl/apiKey/auth/headers/discovery/overrides); credential resolution chain (CLI flag → models.yml → stored OAuth → /login key → env + `.env` layering); Claude Pro/Max + Codex OAuth (PKCE S256, refresh, quota-aware rotation); settings layering engine + `xdev config` CLI; env framework (process env → project `.env` → agent `.env`); approval modes always-ask|write|yolo + per-tool approval record + `bash.patterns` (docs/research/parity-tools-providers.md); role-selector grammar `provider/id:effort@upstream` with alias loop guard; durable credential-block table + quota rotation; failover chains; `promptCacheKey` = sessionId with fork inheritance cleared on model/thinking/tool overrides (omp-context-resilience §1).
- **Session UX** — slash commands (native markdown discovery project+user, quote-aware `$1..$n`/`$@`/`$ARGUMENTS` expansion, unknown-command fall-through); lifecycle `/new` `/fresh` `/clear` `/drop` `/fork`; `--continue`/`--resume` + picker + `switchSession` runtime; `/tree` `/branch`; context files (AGENTS.md/CLAUDE.md hierarchy, `@path` imports) + SYSTEM.md/APPEND_SYSTEM.md variants + `--system-prompt` flags; keybindings remap; `/dump` transcript (docs/research/parity-session-ux.md); session titles (`/rename`, ai-title small-model generation, custom > ai > first-prompt cascade, picker metadata); context-file prompt-injection scanning; three-tier stable→context→volatile prompt-cache assembly (claude-code-internals.md, hermes-internals.md).
- **Agent system** — task-agent discovery (markdown+frontmatter, first-wins merge), spawn policy (allowlist, depth guard, plan-mode read-only children), model precedence; `hub` tool (messaging, jobs, process supervision) + Agent Hub TUI roster; hooks event bus with fail-closed `tool_call`/`tool_result` interception; advisor/watchdog steering; prewalk big→`@smol` model handoff; magic keywords (`ultrathink`/`orchestrate`/`workflowz`); plan mode + `xd://propose`/`xd://resolve` finalization (docs/research/parity-agent-system.md); parent-owned `todo` policy (stripped from subagent tool sets except prewalk-armed children); cross-session messaging (mailbox dirs, SendMessage, InboxPoller idle delivery, accept/hold/off inbound policy) as NICE (claude-code-internals.md).
- **Knowledge & chrome** — memory backend seam + local backend (extraction → session-model consolidation → MEMORY.md + learned.md) + `memory://` read seam; skills (SKILL.md discovery, `skill://` protocol, `/skill:` commands, managed skills); `learn` tool; theme engine (66-token JSON themes, vars, color detection, dark/light auto, symbol presets, live reload); TUI chrome (status-line/HUD segments, overlays, custom tool renderers) (docs/research/parity-knowledge-ui.md); frozen memory snapshots injected at prompt build (not per-turn) to protect prefix cache (hermes pattern).
- **Extended tools & ecosystems (demand-driven)** — eval kernel (py persistent NDJSON cells), notebook virtual text, `web_search` (22-provider chain with constraint relaxation), `github` tool, `ast_grep`/`ast_edit`, browser via chromedp, checkpoint/rewind (session-tree branch + report entry, NOT a git shadow repo), custom subprocess tools, MCP config extensions, LSP tool + `lsp-config`, secrets redaction, context promotion, deferred tool-catalog bridge (`tool_search`/`tool_describe`/`tool_call`), marketplace/plugin manager; v2 modes: vibe (director + workers), collab (E2E encrypted), multi-provider discovery, profiles (docs/research/parity-tools-providers.md).

### Out of scope (research IV.10)

- `stats.db`-scale sidecar databases — keep stats in a tiny rollup table.
- In-process extension loading — replaced by the subprocess protocol.
- Rust N-API natives — Go stdlib + subprocesses cover ~90%; the FS-scan shared cache is the one concept worth re-implementing (M7).
- Marketplace and composer-shape systems until demand exists (theme engine itself is now IN scope — M12 CORE; marketplace/plugin manager is the M13 tail).
- Built-in LSP server management — opt-in-lazy only.
- `go-git` — shell out to `git`.

## 3. Architecture (HLD summary)

### 3.1 Module layout

```text
xdev/
  cmd/xdev/            # CLI entry: tui | print | rpc modes
  internal/ai/         # provider adapters (anthropic, openai-completions, openai-responses, google)
    internal/ai/sse/   #   shared SSE frame reader, unified AssistantEvent, partial-JSON w/ 256B throttle
  internal/agent/      # agent loop: steering channels, tool scheduling, cancellation layers
  internal/session/    # JSONL tree store, entries, buildContext, compaction, blob store, listing
  internal/tool/       # read/write/edit/bash + registry, approvals, OutputSink, env hardening
  internal/tui/        # frame-plan renderer over tcell
  internal/ext/        # subprocess extension protocol (JSONL capability handshake)
  internal/mcp/        # MCP client via official Go SDK
  internal/store/      # pure-Go SQLite: history FTS, stats rollup; blob store in stdlib
  internal/protocol/   # RPC v1/v2 wire types (compatible with omp's where possible)
```

### 3.2 Session core port spec (the heart)

- **On-disk layout:** `~/.xdev/agent/sessions/<encoded-cwd>/<timestamp>_<sessionId>.jsonl` (cwd-bucketized so symlink aliases share a bucket) and `~/.xdev/agent/blobs/<sha256>`. Listing reads only a 4 KiB prefix (plus a bounded 32 KiB tail for lifecycle status), stat-keyed cached, bounded parallel scan — never parses whole files.
- **File format:** JSONL, one JSON object per line. Physically begins with a **fixed-width 256-byte `title` slot** (rename/list never rewrite the body), then a `type:"session"` header (id, timestamp, cwd, title/titleSource, additionalDirectories, previousSessionFiles, providerPromptCacheKey, parentSession), then entries.
- **Entry model:** every entry has `{type, id (8-char), parentId, timestamp}`. History is an **append-only tree + mutable leaf pointer**: an append creates one entry whose `parentId` = current leaf and becomes the leaf; `branch(entryId)` moves only the leaf pointer — nothing is mutated or deleted; `resetLeaf()` starts a new root (`/clear` writes a payload-free `reset_boundary` marker).
- **Entry types:** `message` (full AgentMessage incl. usage/cost), `thinking_level_change`, `model_change` (model map), `service_tier_change`, `compaction` (summary + `firstKeptEntryId` + `tokensBefore`), `branch_summary` (context for abandoned branches), `reset_boundary`, `custom` (opaque, extension-owned via namespaced `customType`; core reserves lifecycle values such as `tool_execution_start`, `session_exit`), `custom_message`. Go shape: `EntryBase` + one pointer per entry type (single-union decode).
- **Context reconstruction** (`buildContext(entries, leaf)`): walk `parentId` leaf→root (cycle-bounded), reverse, derive runtime state from the path (thinking level, the model, service tiers, mode), pick the emission boundary (latest `reset_boundary` or latest compaction: emit summary + entries from `firstKeptEntryId`), convert `message`/`custom_message`/`branch_summary` to model messages, neutralize dangling tool calls, drop unsafe turns. Pure function, unit-testable against pi/omp-generated session files. **Acceptance test: xdev must resume an omp-generated session file and produce an equivalent LLM context** — that one test pins the entire port (research IV.3).
- **Blob store:** sha256 content-addressed files; externalize images/data-URLs to `blob:sha256:<hash>` at omp's thresholds; truncate >500k-char strings with byte-exact exceptions for signed provider blocks; files >8 MiB load via streaming JSONL.
- **Compaction:** thresholds + overflow/incomplete recovery + context promotion first; `handoff` doc generation and provider-native streaming compaction later (LLM prompt engineering, portable as-is).
- **Durability model (deliberately pragmatic):** appends are synchronous in-memory + writer hand-off with **no fsync** (`bufio.Writer` + explicit `Flush()` per append; optional strict-fsync flag for paranoid durability); new ordinary sessions stay memory-only until the first assistant message or `ensureOnDisk()` (no junk files for aborted starts); full rewrites (migrations, moves, repair) are atomic stage-then-rename with an EPERM-safe fallback and commit guard — if a rewrite's durability cannot be proven, the manager **fails closed** rather than silently losing data; persistence errors are **latched** and rethrown on later flush/close; crash forensics via `session_exit` + `tool_execution_start` entries, with the loader synthesizing an `aborted` assistant message on resume.
- **Torn-tail prevention (#122, added 2026-09-14) — what is actually guaranteed:** the store counts the bytes it has committed and verifies the file ends exactly there before every write; a write, flush or fsync failure cuts the file back to that boundary and latches, so a half-record can never poison the record after it. A file longer than committed is read before it is judged: a **partial** tail is this store's own interrupted flush and is cut (reported by `RepairNotice`); a tail ending on a complete line is **another process's history** and the store refuses to append (`ErrConcurrentWriter`) rather than forking the tree or deleting someone else's records; a file that *shrank* is refused the same way. Opening a session never mutates it — the repair happens on the first append — and `Open` will not resume a file reachable by more than one path (`nlink > 1`, since writing through either name silently changes the other). The bound this replaces: an unterminated final line used to make `Open` fail outright, so **one interrupted write bricked the whole session**; measured against 12 real `SIGKILL`s of a writer pushing ~9 MB records, no timing produced a torn tail on macOS/APFS (the kernel commits an append after copying it), which is why the repair is pinned by constructing the byte state directly rather than by racing a kill. `no fsync` above still means what it said: without `Options.StrictFsync`, a power loss can drop the last flushes — what is now impossible is a *partially written record*, and a session file can never again become unreadable.
- **Prompt history:** deliberately a *separate* SQLite/FTS5 subsystem — replay fidelity lives in JSONL, search UX in SQLite; never mixed.

### 3.3 Provider layer

- **Four wire adapters, one shared SSE reader**, hand-rolled over `net/http` (HTTP/2 for free): `data:` frames and `[DONE]` sentinel for OpenAI-family, typed events for Anthropic. Each adapter maps its native stream onto the unified event contract verbatim: `start` → block lifecycle triplets (`text_start/delta/end`, `thinking_*`, `toolcall_*`), `image_end`, terminal `done{reason: stop|length|toolUse}` or `error{reason: aborted|error}`.
- **Partial-JSON tool args:** the final parse at `toolcall_end` is authoritative and strict; when it fails the call is answered with `{}` (never a guessed prefix) and the turn survives — the tool's own required-argument error tells the model to re-issue, so an unparseable blob is never a stream error. Salvaging a prefix is wrong by construction: the relaxed repairer (`internal/ai/sse/partialjson.go`, ~200 LOC port, `ParsePartial`) stops at the first pair it cannot read, so `{"path":"/x" content:"…"}` would become a write of an empty file. `ParsePartial` keeps its streaming/preview role only; the strict parse never routes through it.
- **Watchdogs:** goroutine per stream — first-progress timer + idle timer, reset on every event; expiry aborts into `error{aborted}`. **Preconnect:** warm-up dial on model resolve (saves 100–300 ms on transcontinental hops).
- **Stop-reason maps + quirk tables** ported from pi (they encode years of provider annoyance); provider-owned bounded retries (empty completions, malformed envelopes, capability fallbacks such as retrying without rejected strict-tool fields).
- **Backpressure fix:** bounded event queue (1,024 events). On overflow, coalesce consecutive `*_delta` events of the same block — rendering already coalesces visually; persistence only needs final messages. This removes omp's documented unbounded-queue wart without changing semantics.
- **Cancellation:** `context.Context` chains (session → agent → request); tool execution gets a merged derived context (small `errgroup`-based merge helper; Go has no `AbortSignal.any`).

### 3.4 Agent loop

- One goroutine per turn; tools run on a **bounded worker pool** (same-batch concurrency kept from omp, capped ~4–8).
- **Steering** via `chan Steering{steer|followUp|aside}` consumed at step boundaries; `aside` injects at the next agent step boundary without killing the in-flight tool batch; queued messages preserved, never thrown away.
- **Persistence only on `message_end`** (matching omp); streaming text is never persisted mid-flight.
- **Extension interception** (`tool_call`/`tool_result`) called synchronously through the ext-protocol bus with **per-call timeout + kill switch**. `tool_call` policy blocks fail closed; a *hung* extension is killable — which in-process code cannot offer and a subprocess can.
- **Subagents:** same session core, restricted tool sets + `outputSchema` (permissive/strict enforcement) + `yield` tool; start in-process (cheap goroutines, shared provider pool), move out-of-process later if isolation matters.

- **A blank turn is not a finished turn** (2026-09-17, [#331](https://github.com/FreePeak/xdev/issues/331)): the no-tool-call branch used to end the run on `len(msg.ToolCalls()) == 0` alone, so an assistant turn that streamed only reasoning (thinking block, `stopReason: stop`, no text) — the shape a thinking-mode upstream leaves behind, and the one the gateway's `(context elided)` reasoning echo produces on a tool-loop continuation — ended the session with nothing on screen. `isEmptyAssistant` now gates that branch; a blank turn gets one hidden `EmptyTurnNudgePrompt` user turn (`Attribution: "empty-turn"`) and the loop continues. The bound is **per run** (one bool, same shape as the TTSR interrupt budget), so a model that only ever stalls cannot spend turns on the nudge. `TurnHooks.OnEmptyTurn` names the stall in the transcript; the attribution rides the same three harness-text consumers as the turn-budget wrap-up (replay, rewind, stats).

### 3.5 TUI

- Base: **tcell** (raw, fast, low-alloc) with omp's frame-plan model on top: each frame = mandatory chrome (editor/status/HUD/overlay) + `TerminalFramePlan { history?: {id, rows}, viewport: rows[] }`; transcript blocks in three states — **active** (mutable, viewport-resident), **settled** (finalized, reflows on resize until capacity pressure), **committed** (written into terminal scrollback, caches released).
- **History retirement** offered as batches only under capacity pressure, acknowledged only after the write is accepted — **the terminal's native scrollback is the archive** (no app-side scrollback memory). **Resize** borrows the alt-buffer, recovers the anchor via a DSR (CSI 6n) cursor round-trip, and replays per mode (`rebuild`/`append`/`preserve`). Tool blocks collapse by row budget (0→hidden, 1→label line, 2→folded card, ≥3→full renderer).
  - **Frame plan as shipped (2026-09-14, `internal/tui/rowindex.go`):** xdev keeps its own scrollback (there is no native-scrollback retirement path under tcell), so omp's `ScrollView` contract — render a **prebuilt line buffer** at the offset, never the whole session — is implemented as the row index: one stamped render per block (`blockRend`, a superseded render replaced in place), cumulative row offsets (`start`), and viewport-only materialization. A settled block then costs one struct compare per frame; `draw()` and every scroll key stopped walking the transcript (measured at 85 200 rows: **7.8 ms → 0.50 ms per frame**, `totalLines` 68 µs → O(1)). The **bounded middle trim** rides the same stamp: past the newest `toolRecentResults`=4 results a tool block collapses to a head+tail window with the hidden-row count in the hole, so command output is trimmed before the conversation is, `Ctrl+O` opts a result out, and the full text stays in the session JSONL (the same 400-turn transcript is 85 200 → 12 732 rows). ### 3.6 Tools

- `read`/`write`/`edit`/`bash` **exactly per pi's input schemas** (model familiarity is an asset). omp-style line-numbered snapshots + hashline anchors (`PUT N.=M:`, `MV`, `CUT`, `REM`) are the proven edit UX — pure string ops in Go.
  - **Shipped 2026-09-14 (`edit` speaks omp's dialect).** `edit`'s advertised schema is one required string, `input`: a `[path]` / `[path#tag]` header followed by `PUT`/`CUT`/`REM`/`MV` op lines with `+` body rows — the format omp's own tool documents, so a model that has ever edited in omp writes a call xdev accepts. `PUT <N:` / `PUT >N:` insert before/after a kept line (omp semantics; the earlier prose had them inverted). The structured `{path, ops}` object stays as the internal encoding — same verbs, same range engine — because the harness's own tests and the argument-repair path speak it; it is deliberately not advertised. Every malformed shape observed in live sessions is repaired rather than rejected: `ops` sent as a quoted JSON string (7 calls), `path` pushed inside an op (6), the whole args blob sent as bare patch text, patch text inside `ops`. What still fails teaches: each rejection names the accepted shape, and a `[{"op": …}]` header is refused as "not a file header" instead of being read as a path. Grammar lives in `internal/tool/hashline.go`; the recap prose stays under `MaxToolDescriptionChars` (381/400) because the parameters schema is the uncapped, authoritative channel.
  - **Shipped 2026-09-17 (the two ways a live `edit` call actually fails now teach the fix).** Live xdev sessions produced two recurring rejections, both the model's format rather than a parser bug, and both answered uselessly. (1) `edit: edit: line 2: expected a PUT/CUT/REM/MV op line or a [path] header, got "@@"` — a model that sent a unified diff. (2) `edit: body rows start with "+", got "// …"` — a model that knew the verbs but not the row convention. Three diffs in `internal/tool`: `Execute` strips the grammar's own `edit: ` lead before wrapping it, so a rejection reads `edit: line N: …` and never `edit: edit: …` (`strings.TrimPrefix`, pinned by `TestEditErrorsCarryOnePrefix`); `parseHashline` scans for a hunk header up front (`hashlineDiffRe`, `^@@\s*-?\d`) and names the dialect — "this tool does not take diffs", then the hashline form — instead of letting the diff's `--- a/f` first line become a confusing header error; and the row, header and no-op rejects each name the fix. The `Parameters()` prose now **leads** with the `+` rule (it was at char ~600 of 1100, the first thing a provider that truncates a tool description drops). No behavior change to a well-formed patch.
- `bash`: port `executeBash` semantics; one-shot process spawn (~1 ms in Go, no shell-reuse cache needed) — but port the **env-hardening list** and the **OutputSink byte-for-byte** (fixed head+tail windows; no spill — see §2 row). PTY via `creack/pty` behind the same eligibility predicate (UI + opt-in + env escape hatch).
- Grep/glob/fd: v1 shells out to `rg`/`fd` when present (pi's own answer) with a pure-Go fallback (`fs.WalkDir` + `regexp` + gitignore parsing); v2 ports the pi-walker shared FS-scan cache (TTL, partition by traversal options, empty-result revalidation, invalidate-on-write).
- AST tools: **no tree-sitter embedding** (CGO + memory); shell out to the `ast-grep` binary if present — preserves the CGO-free guarantee.
- Approvals: port the tier model (read-only/write/exec) + `bash.patterns` allow/deny/prompt with conservative compound-command combination; approvals stay **separate** from interception (approval decides *whether to run*, interception routes *to a better tool*); real containment is external sandboxing (document container recipes like pi).

### 3.7 Memory budget (hard <100 MB RSS)

| Component | Budget | Technique |
|---|---|---|
| Go runtime + binary + idle GC heap | 8–15 MB | Standard; `GOGC` tuning, `debug.SetMemoryLimit` as hard backstop |
| Provider HTTP/2 connections + TLS | 3–8 MB | Shared `http.Client`, connection reuse, streaming bodies |
| Session entries in memory (windowed) | 10–30 MB | Materialize only the post-boundary tail (compaction/reset boundary); older entries stay on disk, loaded on demand for list/tree/export |
| In-flight assistant stream state | 1–3 MB | Only the current message materialized |
| Tool output sinks | <1 MB | Fixed head+tail windows, middle bytes **discarded** (OutputSink ported exactly; retention is **#115**, still open) |
| Transcript renders (row index) | 2–6 MB | One stamped render per block, replaced in place; viewport-only frames; aged tool output collapses first (§3.5) — measured 30 MB RSS through a streamed 2 500-line answer |
| JSON decode buffers | 2–5 MB | `json.Decoder` per JSONL line; never unmarshal whole files |
| MCP child servers | 0 (agent RSS) | Child processes; agent holds pipes + tool descriptors only |
| **Total worst case** | **~30–70 MB (est.)** | Enforced via memory limit + bounded structures |

`debug.SetMemoryLimit` is the process backstop: a runaway turn degrades into "compact now" instead of an OOM kill.

### 3.9 Reliability requirements (ported from omp, research IV.9)

1. Append-only JSONL + leaf pointer; no destructive edits.
2. Latched persistence errors; fail-closed indeterminate-write handling; atomic stage-then-rename rewrites.
3. `session_exit` + `tool_execution_start` forensics; synthetic aborted assistant message on resume.
4. Auto-retry with backoff + provider failover + context promotion before compaction.
5. Stream watchdogs (first-progress + idle); bounded provider-owned retries; capability fallbacks.
6. Memory limit as process backstop, so a runaway turn degrades into "compact now".
7. Supply-chain: pin deps exactly, `govulncheck` in CI, single-binary releases with checksums.

   - **O(transcript) per frame.** `draw()` rebuilt the whole row list every frame (30 fps while a turn runs) and `totalLinesLocked()` re-walked every block on each scroll key → 7.8 ms/frame at 85 200 rows. Fixed structurally by the row index (§3.5): 0.50 ms/frame, scroll keys O(1)–O(blocks).
   - **Quadratic inline markdown.** `inlineRuns` consumed plain text one rune at a time via `rest = string([]rune(rest)[1:])`, re-decoding the remainder per character — one 6 000-rune streamed paragraph cost **98 ms to re-render** (and 1.36 s per frame once a message reached ~20 KB), which is the reported 100 % CPU during a long answer. It now jumps marker-to-marker and copies plain runs whole: **4.7 µs** for the same render.
   - **Render cache that never let go.** The per-state map cache kept *every* intermediate render of a streaming block: +1 200 stale entries and **274 MB** heap for one 1 200-delta message. One render per block, replaced in place: 4 000 deltas now cost 14 MB, and a live 2 500-line answer runs at **30 MB RSS / 0.2 % CPU** where the previous build sat at **357 MB / 12 % and climbing** (goal: hard <100 MB RSS).
   - **A frame per input event.** The UI loop painted after *every* event, so a wheel flick queued a whole burst of frames ahead of the keystroke typed behind it: 200 notches cost **296 `Show()` calls** (a synchronous tty write each), and the character waited for that backlog to drain — which is why the lag scaled with how much you had scrolled, and why nothing showed up in the per-frame cost: measured flat at ~0.49 ms per keystroke whether the viewport sat at the top or the tail (14 536 rows), because the row index was already doing its job. `Run()` now drains the input already queued in `keyq` and paints once (`drainKeys()`, bounded at `keyBurst = 256` so a held key still reaches the screen); every event is still applied, in order, so no chord or paste marker is dropped. Regression gate: `TestScrollBurstCostsOneFrameNotOnePerEvent` drives the real `Run()` loop with each flush charged 1 ms and asserts **293–312 frames pre-fix, ≤24 after** — plus that the burst actually scrolled, so an ignored wheel event cannot pass cheaply. An interactive tmux/pty A/B was not usable as evidence: `send-keys` paces the burst itself (~160 ms for 600 notches), so the harness measured tmux rather than xdev.
   - Regression gates: `TestRowIndexAgreesWithFullRebuildAtEveryOffset` (the fast path paints exactly what the full rebuild painted, at every offset), `TestSettledBlocksSurviveTailMutations`, `TestAgedToolOutputCollapsesFirst`, `TestExpandedResultEscapesTrim`, `TestFrameCostFollowsViewportNotSession`, `TestStreamingDeltaCostStaysFlat`.

**Milestone deltas from the second-wave research (2026-09-09, `docs/research/*-internals.md`):** M1 adds the classified-error taxonomy (Flag bitmask + retriable kinds + overflow regexes) and never-executed partial-tool-call stubs; M2 adds todo-state replay (backward scan preferring `user_todo_edit` entries) and the title-resolution cascade; M3 adds the `todo` tool (9 ops, 5 statuses incl. `blocked`+`reason`), the 7-pass tool-arg repair pipeline, file-freshness rejection, backgrounded bash, and out-of-band steering markers; M5 adds the compaction method ladder `[remote, handoff, shake, soft]` with 80% recovery band + dead-end parking, `TurnRecovery` partial-stream rewrite, and fork-on-compression lineage as the audited alternative; M6 adds the `yield` wrapper contract (retry budgets, 12k inline / 4k preview async-result split), `todoPhases` in `get_state`, and the deferred tool-catalog bridge; M9 adds the role-selector grammar `provider/id:effort@upstream` with alias loop guard, the durable credential-block table + quota rotation, and failover chains; M10 adds `/rename` + ai-title generation, context-file injection scanning, and the 3-tier stable→context→volatile prompt-cache assembly; M11 adds the parent-owned `todo` policy (stripped from subagent tool sets) and mailbox-style cross-session messaging (NICE).

## 5. Key decisions

- **Go single static binary, CGO-free** — cross-compiles everywhere, ~22 MB dev / ~29 MB installed with the SQLite-backed mnemopi backend linked in (measured 2026-09-12; build without it to reclaim ~7 MB), instant startup, no runtime install; it is the only way to meet the hard <100 MB RSS budget a JIT-ed JS runtime cannot (research Part III, IV.0.2).
- **Port the data model, not the code** — pi/omp's session tree, stream contract, context reconstruction, OutputSink, and frame-plan TUI are mature, crash-tested designs; porting their semantics (same entry names) buys interop with existing session tooling without carrying JS-era implementation weight (research IV.0.1).
- **Extensions as subprocesses with per-event timeout + SIGKILL** — omp's in-process TS extensions run with full process trust and a stray throw kills the session; a process boundary makes hung extensions killable and extensions language-agnostic, and omp's RPC/host-tool model already proves cross-language embedding works (research II.5, IV.5, IV.8).
- **Bounded queues with delta coalescing** — fixes omp's documented unbounded-queue wart without changing semantics: on overflow of the 1,024-event queue, coalesce consecutive `*_delta` events of the same block; rendering coalesces visually and persistence only needs final messages (research II.3, IV.4).
- **tcell over bubbletea** — bubbletea's Elm event model adds allocation churn; tcell is raw, fast, low-alloc, and omp's frame-plan model ports cleanly on top (research IV.6).
- **Pure-Go SQLite (`ncruces/go-sqlite3` or `modernc.org/sqlite`)** — keeps the CGO-free guarantee while providing FTS5 for prompt history; replay fidelity stays in JSONL, search UX in SQLite, never mixed (research Part V, II.2).
- **Shell out to `rg`/`fd`/`ast-grep`; no tree-sitter embedding** — embedding tree-sitter means CGO + memory; Go stdlib + subprocesses cover ~90% of the Rust natives; the one natives concept worth re-implementing in-process is the FS-scan shared cache (research IV.7, IV.10).
- **Product name xdev; research codename `adze` superseded** — the repo name (`FreePeak/xdev`) is authoritative: binary `xdev`, module `github.com/FreePeak/xdev`, data dir `~/.xdev/agent/`; session format remains compatible with omp's.
- **Prompt reality check (2026-09-09 primary sources)** — pi's real base prompt measures ~460–510 tokens over 8 built-ins; omp's full 29-tool slate costs ~12–15k tokens (hashline edit mode alone 5.3 KB). xdev ships the pi-minimal core plus an ESSENTIAL gate: the top-level tool schema carries only essential tools; discoverable tools are demoted behind `xd://` devices and search (parity-omp-internals.md §4).
- **Todo state rides the transcript** — todo phases persist as tool-result `details.phases` plus `user_todo_edit` custom entries (omp v18), replayed by backward scan on branch switch/rewind; NOT side files (Claude Code `tasks/`) and NOT a SQLite table (opencode) — the replayable transcript stays the single source of truth (omp-todos-internals.md §6).
- **Injected content is hostile until scanned** — AGENTS.md-class files and web/browser/MCP tool output pass prompt-injection threat scanning and `<untrusted_tool_result>` wrapping (hermes pattern) before entering context (hermes-internals.md).
- **A standing convention lives in a context file, never only in recall** — xdev puts text into the prompt through two channels that look interchangeable when you write a rule down, and are not. `LoadContextFiles` (`prompt.go:281`) injects `~/.xdev/agent/AGENTS.md` and then the `AGENTS.md`/`CLAUDE.md` chain root→cwd under a **32 KB** cap, every turn, framed as authoritative; `rules.Discover` (`rules.go:133`) does the same for native `RULES.md` (`AlwaysApply`, native priority) and the `.cursor`/`.agent`/plugin sources. Auto-recall instead ranks notes against **the last user turn only** (`RecallContextTurns = 1`), caches 60 s, and is hard-capped at **1024 tokens = 4096 chars** with *"Heuristic context recalled from earlier sessions — not authoritative"* prepended (`hindsight.go:588-590`). Measured 2026-09-17 against the live bank: one query returned 8 notes / 8756 chars, so `capRecall` kept 2 notes and part of a third and dropped the rest — a worktree convention that lived only in the bank sat at char 4357 of a 4096-char window. Where it did survive, the block's own framing did the rest: a session read the rule, called it *"a recalled instruction from earlier sessions … heavy for a one-line helper"*, and did not follow it. So: cross-repo habits → `~/.xdev/agent/AGENTS.md`, repo invariants → `<repo>/AGENTS.md`, must-apply-even-when-shadowed rules → `<repo>/RULES.md`; recall carries facts that inform a plan and may be missed, not policy ([decision](decisions/standing-conventions-location.md)).

### 5.1 Claude Code cross-check (adopt / verify / reject)

A batch of questions is ONE tabbed card (not N interruptions), every question carries a free-text row, and a "Chat about this" escape closes the card unanswered so the human can answer in prose.

- **Edit-tool semantics refinement** (M3) — CC's exact-string Edit with uniqueness + read-before-edit staleness gates complements the hashline UX; also adopt the benign-exit-1 command list and output-to-file overflow pattern for `bash`.

**Verify:**

**Reject (with reasons):**

Net: Claude Code **confirms xdev's pi/omp-shaped minimalism** (it lacks LSP/AST/memory-DB too) while contributing five features omp lacks entirely: microcompact, ExitPlanMode gate, AskUserQuestion, checkpoints/rewind, and the hooks blocking contract.

### 5.2 fx cross-check (adopt / verify / reject)

fx ([`vercel-labs/fx`](https://github.com/vercel-labs/fx), Zig, `ced6180` = v0.0.9; 671,361 lines across 587 files) was studied from a full clone on 2026-09-13 across nine domains — budgets, session core, providers/auth, tools, permissions/execution, TUI, extensibility, embedding, engineering discipline. It is xdev's closest live peer (tiny native single binary, no JS runtime, minimal tool slate, inspectable sessions) and the only reference agent that publishes **machine-checked** budgets. Evidence with `path:line` refs: [docs/research/fx-internals.md](research/fx-internals.md).

**Adopt:**
- **A repository is not a configuration authority** (M9, **#114**, P0). fx's project `.fx.json` accepts exactly three repo-safe keys (`max_agent_steps`, `max_tool_result_bytes`, `context`) and ignores profile-owned ones; the docs give the reason — *"This prevents a repository from silently changing your model preferences"*. xdev layers `<repo>/.xdev/config.yml` over the user's config with the **same schema**, and a throwaway `-overlay` probe at `7c19a54` proved a temp repo could resolve `approvalMode: yolo`, get its declared `bash.interceptor` **executed** with the inherited environment, and redirect a provider `baseUrl`. This corrects §1 goal 4, which conflated user-YOLO with repo-YOLO.
  - **Shipped 2026-09-14 (23173dd), stricter than fx's three keys and stricter than a denylist.** The allowlist is keyed per layer and lives in one file, `internal/config/reposafe.go`: `.xdev/config.yml` keeps the interface (`theme`, `colorBlindMode`, `statusLine`, `showThinking`), the caps (`memoryLimit`, `maxTurns`, `compaction`, `branchSummary`, `experimentalContextManagement`, `models`) and `ask`/`tts`; `.xdev/models.yml` keeps what-a-model-is metadata and the transport dialect and loses every destination and credential, including `${VAR}` expansion, which now runs on the profile alone. A key added to the schema is repository-unreachable until someone lists it deliberately. On a provider both layers name, the profile wins outright. `.xdev/secrets.yml` may add entries and no longer shadow a profile one — redaction matches on the value, so a clone that replaced `GITHUB_TOKEN` with a dummy would have unmasked a secret it never had. Nothing is dropped quietly: one startup notice per repository file names every refused key and the profile path that may set it. Proven end to end with the real binary, and the tests sit at the seam the loop calls (`LoadSettings` → `Policy` → `ReviewBash`), each checked to fail with the guard removed — the class of defect this repo has documented three times.
- **Measure the request; name the budgets; report every clip** (M5, **#116**). fx triggers compaction from the **serialized request body** and calibrates against the provider's returned `usage.input_tokens` (`orchestrator.zig:6831-6908, 366-384`), with exact integer ratios as the contract (high-water `usable×4/5`, target `/10`, tail `/20`, soft ceiling `/4`, source `/8`, one anti-recompaction guard), retention cut only at complete execution steps ("Payloads are measured, never shortened"), **11 named byte budgets** over injected context (`context_limits.zig:20-29`) settable to `"off"` behind a 64 MiB emergency ceiling and overridable by repeatable `--context-limit name=bytes`, and the rule that *"truncated or omitted context is reported to the runtime rather than silently treated as complete"*. xdev estimates at 4 bytes/token against anonymous constants.
- **Retain what you truncate, and give the model a door back** (M3, **#115**): 16 KiB spill threshold, 4 KiB preview, content-addressed handle, ≤8 MiB retained, one tool for byte ranges *and* literal search over the retained bytes. xdev discards the middle.
- **`auto` = one bounded second-model review, as an opt-in tier** (M9, **#117**): a fixed small reviewer per provider (not user-selectable), `maxOutputTokens 2048`, ≤16 KiB packet, 64 holds + 64 unavailable attempts per turn; `caution` **only** for concrete injection or malice; a clear verdict authorizes the exact unchanged action; caution/incomplete/unavailable holds that action and returns guidance instead of prompting or aborting; headless with no prompter denies, traced. This answers §5.1's open "CC's `auto` mode — pluggable, off-by-default" line with a shipped design. YOLO stays xdev's default.
- **Containment without a sandbox** (part of #114/#117): auto-run only a fixed read-only command allowlist, executed in a **3-variable scrubbed environment** (`PATH=/usr/bin:/bin`, no `HOME`, git env neutralized) — provably no ambient authority.
- **Write-side durability set** (M2, **#122**): one buffer per turn batch, `file.length() == committed_bytes` asserted before writing (foreign-writer detection), positional write, `sync()`, `setLength` rollback on failure, unfinished trailing turn discarded at open, 0700/0600 with a lock deadline; plus a recover/migrate verb pair and a doctor that prints the exact repair command (**#121**).
- **Credential storage is verified at use time** (M9, **#123**): macOS Keychain by shell-out to `/usr/bin/security` (CGO-free, same philosophy as our `rg`/`fd`/`git` shell-outs), and where a file is the store, `mode == 0600 && nlink == 1` is re-checked before trust with the parent forced 0700 and a hard failure otherwise; an explicitly named credential source is an exact authority whose absence **never** falls through to another billing boundary.
  - **Shipped 2026-09-14 (4ff976e, f8ddc2c), with the Keychain write lane rejected by measurement.** What xdev does now: `credentials.json` is verified **on every read** (`mode == 0600 && nlink == 1`, refusal names the repair), the data dir is tightened to 0700 on write, and an explicitly named credential is an exact authority — `auth: oauth` with no OAuth login, or a `keychain:` reference that cannot be satisfied, errors instead of falling through to a key or an environment variable (the silent account swap). The Keychain is a **source**, reachable as `providers.<p>.apiKey: keychain:<service>[/<account>]`, and never a sink: `/usr/bin/security` takes a secret either as an argument (world-readable in `ps`) or through a prompt that [measured as silently truncating at 128 bytes](decisions/keychain-credential-source.md) with exit 0 — fine for an API key, corrupting for a 1–2 KB JWT. Reads carry arbitrary length (verified byte-exact at 8 KiB, and end to end through `ResolveCredential` at 2 KB against the real tool). Token zeroization is not implemented and is not available: Go strings are immutable, so the practical control is that secrets are never retained beyond the request and never logged whole (`Redact`, tested).
- **Budgets a machine enforces** (M8, **#118/#119**): 2 ms mean startup per command on one authoritative runner with a default new commands inherit, hyperfine at 100 runs/10 warmups against a **seeded worst-case store** (8 sessions × 256 MiB sparse logs) and a baseline reported but never subtracted; frames at 8/12/17 ms p50/p90/p95 with thread/fd/RSS deltas as the leak check; ratio-based gates for shared runners; a base-vs-head size **delta** warning (52,429 B) in PR CI with the hard ceiling reserved for release (7.800 MiB + 0.250 MiB headroom); a ship gate that jq-asserts the Actions **job-name set** so a skipped matrix row fails; and `check-public-surface.sh` — a tracked-tree leak audit for `/Users/<name>/` paths, token-shaped strings and fixture hygiene — inside PR CI. xdev already has the memory proof, the fuzzers and govulncheck; these three close the time/size/integrity blind spots.
- **A tape tier between unit tests and tmux** (M4, **#120**): `FX_DEBUG_RECORD=1` → `.fxtape`; `fx replay <tape> --golden out.txt` needs **no PTY**, so a user's render bug becomes a checked-in golden diff (SHA-256 cell-grid hashes; screenshots explicitly *not* the oracle), under the rule "pick the lowest layer that can observe it".
- **Target-scoped instructions** (M10, evidence for **#108**): fx resolves the `AGENTS.md` chain **per tool-call target** at call time (narrowest scope wins, user request outranks project text), delivered as entity-escaped wrappers with per-file and total byte budgets, and refreshed before continued turns — exactly the consumer `Rulebook.ForPath` never got, and the escape half is the cheap companion to #81's scanner.
- **Ready-gate prose** (docs, folded into #119): *"Do not document intended behavior as if it already exists"*, and never say ready/done/complete until you personally ran the built binary and drove one real interaction, because tests "do not always construct the full runtime, attach a TTY, or spawn background threads" (`AGENTS.md:5-17`). That is this repo's own recurring defect class, named as a rule.
- **Detached commands stay the model's to finish** (M3, **#127**): fx's `shell` is one tool with `run`/`interact`/`stop`; `yield_time_ms:0` returns an execution handle that stays addressable across turns (64 live + 32 tombstones, persisted with the session), `interact` re-observes or sends exact bytes, `stop` terminates the group. xdev starts such jobs (`run_in_background`, #16) and hands back a job id + output path, but exposes no control: `Stop`/`WriteInput`/`Logs` exist only on the hub's *named-service* table (`internal/agent/proc.go:297,380,254`), and `cmd/xdev/pscmd.go:160-166` records that neither registry is persisted. Clone by unifying the registries, not by adding a second control surface.
  - **Shipped 2026-09-14 (0fed6f3), one control surface instead of two.** The verbs went onto `bash` itself (`action=status|logs|stop|write`, `job=<id>`) because the issue's own diagnosis was two registries with one inert — a second control plane would have recreated the split. Each job now carries the two things that make it addressable: its process-group id and a stdin pipe kept open, so a detached REPL, watcher or `y/N` prompt is a conversation instead of a dead end. `stop` waits for the reaper so the state it reports is final (the #126 guarantee, applied to a job); an unknown id is refused at the seam by every verb; a timeout handoff honestly reports `stdin: not writable`; and eviction prefers finished jobs, warning in the start response when a live handle must go. Verified live by driving the built binary as the model across four turns (`write hello-world\n` → `logs` → `ECHO:hello-world` → `stop` → `signal 15`). The persisted-handle half (fx's 64+32 records travelling with the session) is **#243**, needing a session entry type, a probe-and-re-register on resume, and host validation.

**Verify:**
- **Alt-screen chat vs inline bands** (#78). fx never owns the screen in chat: row bands with *typed* owner violations (`PreservedShellMutation`, `WriteOutsideBand`), scrolled-off lines pushed into the terminal's **real scrollback**, `?1049h` only for overlays, and a diff emitter that feeds accepted bytes back through its own VT emulator to detect and repair a partially-applied scroll. Judged against this, our frame-plan tail may be re-scoped rather than implemented.
- **Capability tables beat runtime "unsupported"** (informs #98, #84, #85). A provider is a `Bundle` of optional parts and `gateway_only()` yields a **shrunk set**; a comptime 21-bool profile with `allows()` is guarded by tests that fail if a capability is enabled next to its host-backed substitute — the cheapest known guard against "engine landed, arming absent", which is xdev's most-repeated defect.
- **Snapshot-in-response instead of update notifications** (#100). fx's `session/set_mode`/`set_config_option` are **ack-only** (no `current_mode_update`/`config_option_update` anywhere) yet stay correct because `session/new|load` return the full `configOptions` array. Decide which shape we want before implementing #100's mode box — and note fx's warning: it advertises `loadSession:true` while parsing client `fs/*`/`terminal/*` capabilities it never reads and emitting `available_commands_update` hard-coded to `"[]"`.
- **Named-persistent children** (#91, #94): `subagent{action: run | message}`, `message` continuing a named child by conversation, mid-task feedback that does not interrupt the running tool, `work_id`/generation staleness rejection, parent-routed approvals with hashed stable ids, `cloneToolsWithoutSubagent` depth-1, ≤256 children, and "delegation cannot grant a child broader access" as code rather than advice.
- **Four hook events are the minimal cut** (#92/#94/#113): `PreToolUse` (continue / rewrite_arguments / block), `Stop` (one synthetic continuation only), `PostTurnEnd`, `AttentionRequired{permission|question|route_recovery}` — xdev's set maps 1:1, which argues the cut is right; fx's *delivery* (compiled-in, frozen registry, no third party) is the opposite of our subprocess protocol and stays rejected.
- **Effort tiers from the advertised list** (#98, #105) — `reasoning_efforts` per model with a `max`→highest-accepted mapping, vs xdev pinning effort per provider.
- **Title cascade shape** (#107): 240 B manifest field + a derived ≤16 KiB display sidecar + a separate bounded generator call (≤60 B output, 2 KiB excerpt, 15 s, 128 tokens, sanitized *before* stripping), and one remembered model **per provider** so switching back restores it (#105).
- **Whether `web_search` wants chain depth at all** (#110): fx has two providers behind one gateway (Exa→Parallel), no client-side chain, ≤100k result chars, and separate `web_search`/`web_fetch` with hop/time/URL caps. Supports the "3-chain + relaxation is the parity stance" branch.

**Reject (with reasons):**
- **Linear session log.** No `parentId`, no leaf pointer, no fork/branch/rewind anywhere in fx's session core — validator-enforced linearity bought by giving up rewind, `/tree`, `/branch` and `/fork`. xdev keeps the tree and takes only the *coverage-seq watermark* idea (#83).
- **WASM / N-API embedding.** A 36-field hand-written injection struct plus 28 host imports is Zig-cost engineering; Go cannot do it CGO-free. xdev's embed story stays `rpc` + `acp` + `print`, and the one idea worth stealing (a host-owned `fetch`/transport seam for tenancy and quota — fx's is 88 lines) needs no new artifact.
- **PGSO.** Profile-guided *size* codegen via pinned LLVM has no Go equivalent; the transplantable pieces are the ceiling+reserved-headroom framing (#118) and the mandatory test-inventory classification (#119).
- **Default-on LLM review, and any in-process permission theater.** §1 goal 4 stands; #117 is opt-in and cost-disclosed (fx bills the review as an extra request and says so).
- **Deleting the learning layer.** fx removed its memory tool outright in 0.0.8 and ships no todo tool, no eval kernel, no LSP, no AST, no regex grep, no browser. Both are omp-parity requirements for xdev (M3/M12/M13) — a peer's absence is not evidence of low value, only of different scope; it *is* evidence for keeping those seams demand-gated (#85, #87, #112).

**What fx does to the stated non-goals (§1).** *No JS/Bun runtime, no in-process plugin VM, no Rust N-API natives* — fx is the counterfactual test and it passes: 671k lines of Zig with `.dependencies = .{}`, extensions compiled into the binary behind four frozen in-process hook events, and its embeddability bought with ~30 hand-written `{context, fn-pointer}` vtables, 28 `fx_*` host imports and a neutered WASI — the honest price of an in-process plugin surface, and exactly the cost §1.5 refuses to pay (xdev's foreign code crosses a process boundary and gets killed per event). *No built-in permission/security system* — fx proves that stance and then proves the non-goal was conflating two things: it has zero OS containment, yet its policy layer is rigorous (static-grammar read-only allowlist, 3-variable scrubbed direct-exec environment, fail-closed defaults, exact-action authority). Containment is not what makes YOLO safe to ship; **the admission gate is**. Which is also why the §1 "containment belongs to external sandboxing" line cannot excuse #114: an external sandbox bounds the *process*, never the *configuration source*, so a repo-written `bash.interceptor` runs happily inside it. Goals 1–2 fare better in the abstract and worse in practice — fx has no process-level RSS gate at all (memory bounded per structure), so xdev's <100 MB budget stays the differentiator, but only as good as its proof step: the guarantee itself held (`go test ./...` at `ci.yml:55` runs the worst-case test unfiltered), while the **dedicated** gctrace proof could not fail on its own verdict (`| tail -40` with no `pipefail`) and is skipped entirely whenever that earlier step fails — the purpose-built signal was the dark one. Masking fixed in `e03fce2`; the gate ordering that hides five further steps is #119's business.

**xdev is measurably ahead** on: a hard <100 MB RSS budget with a CI memory proof (fx has **no** process-level memory gate at all — memory is bounded per structure, never per process), windowed materialization (fx's `events.jsonl` grows forever and listing full-parses every log), session listing by prefix reads, tree/branch/rewind, wire-transport breadth (four v1 transports + any-baseUrl + an offline bundled catalog + per-model cost data; fx has three gateway-shaped routes and **no** direct Anthropic/Google/chat-completions route — its only local story is a loopback endpoint that must speak its own gateway spec, so plain `ollama` is incompatible — and it never receives price data), stream watchdogs + partial-stream retain-and-continue (fx has no client-side inter-token idle watchdog), subprocess extensions with third-party hooks + custom markdown slash commands, the todo engine, regex search via `rg`, LSP/AST tools, and the eval kernel.

Net: fx **confirms the thesis from the other language** — 5,450-byte system prompt, 17 tools with 15 advertised, hand-rolled transports, no telemetry, no in-process plugins, no marketplace, and no OS sandbox despite advertising a `sandbox` key. What it exposes is not a missing feature but a missing **contract**: budgets, boundaries and provenance that CI enforces — plus one finding that is an active defect rather than a gap (#114).

### 5.4 DeepSeek dsh + OpenCode cross-check (2026-09-14)

Two more harnesses were studied after §5.3, chosen because each is the strongest witness in an area
xdev's existing sweeps left thin: **OpenCode** (`anomalyco/opencode`, TS/Bun, **v1.18.30** @
`228e909`, full clone — supersedes the v1.18.28 binary forensics in
[research/opencode-internals.md](research/opencode-internals.md)) is the only one of the four whose
**LSP manager is always on for the write path**, and **dsh** (`deepseek-ai/deepseek-harness`, TS on
the Cordis plugin kernel, **`dsh-v0.1.5-rc.2`**, a developer preview with prerelease tags and no stable release; `SAFETY.md` says it "has not undergone a security audit") is the
most complete *harness layer* ever studied here — a session engine, a durable scheduler, a
background-job ledger, and a code-execution tool that closes most of the token surface a normal
harness opens. Evidence: [research/dsh-internals.md](research/dsh-internals.md),
[research/opencode-internals.md](research/opencode-internals.md),
[research/tool-inventories/deepseek-harness.md](research/tool-inventories/deepseek-harness.md),
[parity/harness-cross-check-2026-09-14.md](parity/harness-cross-check-2026-09-14.md) (every row
dispositioned).

**Quote-integrity caveat (applies to all three docs).** The first drafts of these verdicts were written by subagents whose job was "quote or don't say it"; an audit afterwards found **41 of 85 quoted "verbatim" spans were paraphrases wearing quotation marks** — and one doc cited a source file that does not exist in the corpus (`docs/subsystems/tool-run-code.md`) plus ~6 xdev paths that had moved. All of it was deleted, re-quoted against the corpus, or re-anchored. The surviving rule for anyone reading these sections: a `path:line` citation is not evidence until it resolves, and a quote inside quotation marks is a claim about bytes.

**Adopt:**
- **LSP as a first-class tool with configuration depth** (M13, **#261**, **#263**, **#264**, P1).
  Two distinct facts, verified separately in the clone: OpenCode's **model-facing `lsp` tool is
  experimental and off by default** (`packages/opencode/src/tool/registry.ts:247`,
  `flags.experimentalLspTool`) — while its **LSP service is unconditional on the write path**
  (`packages/opencode/src/tool/edit.ts:197-203` calls `lsp.touchFile` then appends "LSP errors
  detected in this file, please fix" to the tool output, with no flag in that file). So the cheap,
  high-value half for xdev is **#263** (post-edit diagnostics on the result), not a bigger tool. The
  config-depth half is **#261**, and its `settings` / `isLinter` / `warmupTimeoutMs` / merge-chain
  schema belongs to **omp's** `lsp-config` (`docs/research/parity-tools-providers.md` §H), not
  OpenCode — whose chain is narrower and worth copying for the right reason: 37 distinct built-in server ids
  (`packages/opencode/src/lsp/server.ts`), config entries overriding by name and `disabled` deleting
  the name outright (`packages/opencode/src/lsp/lsp.ts:153-166`), and a client-side
  `configurationValue(settings, section)` extraction for `workspace/didChangeConfiguration`
  (`packages/opencode/src/lsp/client.ts:107`). xdev has the 8-op tool (`internal/lsp/tool.go:63`),
  `CachedDiagnostics`, four default servers, and none of that.
- **Deny-aware tool advertisement, scoped honestly** (M3, P1; **PRD-only** this round). OpenCode's
  `visibleTools()` (`packages/opencode/src/permission/index.ts:216`) drops a denied tool from what the
  model is offered — but it is applied to the **MCP catalog only** (`tool/registry.ts:286`,
  `tool/code-mode.ts:210`); its built-ins are always advertised and refused at call time via
  `ctx.ask`. So this is a real xdev gap in exactly the place xdev has the same shape — deferred/MCP
  tools — and not a general "never advertise a denied tool" rule. xdev resolves policy per call
  (`internal/agent/loop.go:1020`) and advertises everything eager (`Registry.Defs()`,
  `internal/tool/tool.go:162`, with `plan-mode`'s `propose` already proving the advertisement can be
  gated on state at `internal/agent/loop.go:836-845`). (dsh states the converse as a security
  invariant — "visibility … do[es] not create a parent-to-child grant lattice" — which is why this is
  a UX token claim, not a safety one.)
- **Search the prior sessions, from inside the session** (M2, **#262**, P1). dsh's `session_search` is a model tool over the session corpus — one strongest match per session, title plus excerpt — with four siblings (`session_event_search`, `session_event_read`, `session_trace`, `session_event_trace`) that make "what did we decide about X last week" answerable in one call; xdev's search is a CLI command (`cmd/xdev/searchcmd.go:31`) the model cannot invoke. Post-compaction, that gap is exactly what **#137** needs a supplier for. OpenCode is the honest negative control: its `home-session-search` is a UI picker over titles, **not** a model tool.
- **Forward-compat contracts on the session log** (M2, **#265**, P1). dsh requires an explicit `ignorable` marker on event types (unknown-and-unmarked = **refuse to reconstruct**, because an unrecognized event "may change how the rest of the log is interpreted"), a `request/header` envelope logged per turn so "every conversation request is a pure function of the log", a `SessionFormatUnsupportedError` that survives "only as refusal diagnostics" naming the raw log, and a projection-cache invalidation version that keys cold caches. xdev's loader parses unknown types into opaque nodes and keeps chain connectivity — tolerant, with no way to mark which entries are safe to lose.
- **`run_code` / programmatic tool calling** (M6, **#268**, P2, gated). dsh's PTC executes the model's program *in a worker thread whose only host bridge is the tool-call route*, so a model can loop, branch, and compose tools in one call and N intermediate contexts never enter the transcript. xdev already owns the kernel and NDJSON frame protocol (`internal/eval`); the delta is one injected binding. **Ship a token-savings benchmark with it, not after it.**
- **Measure the request at the revision you computed it at** (M5, enriches **#116**, P1). dsh's `logRevision` "is the number of durable events consumed for every field in the measurement", and every node of the current surface is priced under one declared route. That is the honest version of §5.2's measure-the-body rule: a budget number without the revision it was measured at cannot be audited, which is exactly what makes an over-refuse guardrail arguable.
- **A truncation marker that says what happened to the bytes** (M3, **#115**, P1). dsh's spill seam returns a locator **plus a `retrievalHint`** so the consumer never assumes a retrieval mechanism, keeps `source` as *provenance, never access control*, and refuses loudly on a real storage failure. xdev's marker (`internal/tool/sink.go:30`) promises only first/last bytes — which is true; the failure is that the middle is gone and nothing says so in a form the model can act on.
- **A durable child-session id, so a subagent can be continued instead of re-spawned** (M11, new
  issue this pass — **#271**, P2). OpenCode's `task` accepts an optional `task_id` so "the task will
  continue the same subagent session as before instead of creating a fresh one"
  (`packages/opencode/src/tool/task.ts:47-49`, resolved at `:136`) — xdev's `task` always spawns, so a
  long fan-out re-pays its setup cost every round. dsh's session seam solves the same problem one
  layer down and names the guard xdev lacks: `delegationDepth` is a **durable header** whose
  "absence means top-level depth zero," and "the greater present value is authoritative … cold resume
  cannot lower it" (`docs/subsystems/subagent.md` §In-process backends) — so a resumed child cannot
  inherit a shallower depth and recurse further than a live one. xdev has a hardcoded in-process
  `maxDepth = 2` (`internal/agent/task.go:231`) with nothing durable behind it; **#191** already owns
  the machine-readable cap refusal, so **#271** is only the id + the durable depth.

- OpenCode does **not** rely on the provider's overflow error alone: it checks `isOverflow` against the *previous* turn's reported usage before building the request (`packages/opencode/src/session/prompt.ts:1164`) and again on live usage mid-stream (`packages/opencode/src/session/processor.ts:493`). But its proactive estimator is `Token.estimate(JSON.stringify(msgs))` (`packages/opencode/src/session/compaction.ts:220`) — a serialize-and-guess over the message array, i.e. precisely the number **#116** says not to trust. Both harnesses converge on the same correction; measure-the-body beats neither trigger.
- Compaction-as-error-path vs. §5.2's over-refuse guardrail — OpenCode never summarizes *proactively* and relies on the provider's overflow error to trigger it. Cheaper, and it risks a whole failed request; needs a measured comparison before it can be considered for **#137**'s trigger table.
- dsh's `every_seconds >= 300` floor, latest-due collapse, and fixed-rate anchoring vs **#162**'s design — the collapse rule (a sleeping machine fires once, not N times) is portable; the "no cron grammar in v1" decision is not, because xdev's `#125` cron parser already exists.
- dsh's `reported` flag (a completion notice suppressed once another reporter has committed to deliver it) vs **#244**'s completion-notify path — this is the dedupe xdev needs before a second notifier lands, not after.

**Reject (with reasons):**
- **Delegation-as-authority-model.** dsh's `toolFilter` narrows a child's *view* and says so in the docs — it "does not create a parent-to-child grant lattice" — while xdev's `resolveAgentTools` (`internal/agent/task.go:368`) intersects declared ∩ parent ∩ allowlist, which *is* a grant model. xdev's is stricter; don't relax it toward dsh's.
- **A 57-name tool registry (dsh: 26 packages, ~57 renameable model-facing names) and OpenCode's 16 built-ins plus custom files plus the whole MCP catalog** — restates §1's pi-minimal stance and §5.1's verdict. xdev ships one tool per capability and routes the long tail through MCP.
- **Client/server split, web/desktop apps, plugin slot systems, provider wire-compat shims, TUI fullscreen diff viewers as a *framework*** — platform surface for a single Go binary with 63 commands; the one portable fragment (a staged-diff composer) is **#266**.
- **dsh's declarative state machine as a rewrite of `goal`** — xdev's goal store is one file with one writer; adopt the compare-and-set *vocabulary* inside **#244**, not the architecture.
- **Webhook-triggered auto-spawned sessions** — inbound prompt injection into a fresh agent with no content scanner (§5.3's #81 is still open). That is a remote-control surface, not a feature.

**Also corrected in this pass:** §3's stale "artifact spill" claims (line 43 already says there is **no** spill — middle bytes are discarded, **#115** is open), §3.6's "five edit modes behind one `edit` tool (…apply_patch…)" — xdev ships hashline only, `apply_patch` has no production caller and the schema drift is **#267** — and §3.3's partial-JSON row, which now states the final parse is strict rather than describing a repairer the code does not use.

Net: both harnesses **confirm the §5.1/§5.2/§5.3 verdict** — xdev's minimalism is deliberate and defensible — and each contributed one thing no earlier sweep did: OpenCode proved the LSP tool is the deepest single gap in xdev's surface (**#261**/**#263**/**#264**), and dsh proved that the expensive part of a harness is not the tools, it is the *durability contracts under them* (**#265**, **#271**, **#115**, **#137**).

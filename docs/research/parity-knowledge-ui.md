## F1. Memory subsystem (5 backends, `memory.backend` in config.yml / `/settings`)
**What**: Pluggable long-term memory. Backends: `off` (default), `local`, `hindsight` (remote HTTP), `mnemopi` (local SQLite), `sharpshooter` (friction-gated decision files, background-consolidated).
**Key semantics** (omp://docs/memory.md, mnemosyne-memory-backend.md):
- Injection: "Memory Guidance" block into system prompt at session start from consolidated summary + lessons, shared cap `memories.summaryInjectionTokenLimit` (5000 tok). Memory = heuristic context, not authoritative; cite artifact path when it changes the plan.
- `memory://` URL seam via the `read` tool: `memory://root` (injected summary), `memory://root/MEMORY.md`, `memory://root/learned.md`, `memory://root/skills/<name>/SKILL.md`, and `memory://<memory-id>` for full Mnemopi rows (YAML frontmatter header; recall previews are 500-char clipped with trailing `…` — full read is MANDATORY before `memory_edit update`). This seam is the key parity point.
- `/memory` command: `view|stats|diagnose|queue|sync|clear|reset|enqueue|rebuild`, plus `mm …` (Hindsight mental models: list/show/refresh/history/seed/delete/reload). Backend-interface dispatch, not per-backend commands.
- **Local backend pipeline (two-phase, background at startup)**: Phase 1 — per-session extraction by `default` role model over changed persisted sessions (skips subagents, non-persisted, idle <12h, older than 30d; caps: 64/startup, 300 scan, 8-way concurrency, 120s lease, 4000-tok input, 0.7 context fraction). Phase 2 — `smol` role consolidation (180s lease, 30s heartbeat) producing `MEMORY.md` + `memory_summary.md` + generated `skills/` playbooks. Lease+heartbeat prevents double-run; stale skill dirs pruned; secrets redacted before write; `learned.md` never overwritten by consolidation. Prompt templates are static files (stage_one_system, stage_one_input, consolidation_system, consolidation, read-path).
- Model selection piggybacks the model-role system with fallback chain: requested role → `default` → session model → first registry model.
- Mnemopi: local SQLite banks, scoping `global|per-project|per-project-tagged` (project = basename + hash of abs cwd), autoRecall first turn, autoRetain every N turns (4), FTS or embeddings (local bge-base-en / multilingual-e5, or remote OpenAI-compatible), optional LLM `llmMode: smol|remote|none`. Best-effort startup — failure leaves session usable, tools report "not initialised". Durability: exit drain 1.5s (retain + flush in-flight, no sleep); `/memory enqueue` = strong boundary (retain + flush + sleep/consolidation, age-gated at workingMemoryTtlHours/2).
- Hindsight: remote server (default localhost:8888, token), bank scoping (default per-project-tagged: project tag = lowercase basename of git primary checkout root), auto-recall first turn, auto-retain every 3 user turns, mental-model seeds (`user-preferences`, `project-conventions`, `project-decisions`) cached as `<mental_models>` prompt block (refresh 5min, 16k render cap). `memory_edit` not available for Hindsight/local.
- Config: `memories.*` (~15 knobs in memory.md); `mnemopi.*` (~20); `hindsight.*` + 18 env overrides; HINDSIGHT_*/MNEMOPI_* env precedence over yaml.
**Surface**: `memory.backend`, `/memory` subcommands, `autolearn.enabled`, `memory://` read URLs, settings keys above.
**Go port**: Stdlib: YAML config + JSON/markdown files, `database/sql`+modernc.org/sqlite or pure-file storage; model calls re-use the agent loop's provider client. Hindsight = thin net/http client. Two-phase pipeline = bounded goroutine pool at startup (leases via SQLite row locks). Keep sharpshooter as v2.
**Parity**: local backend + `memory://` seam + `/memory view|clear|sync` = **CORE** (user named memory). Mnemopi (FTS5-only first, embeddings later) = **NICE**. Hindsight = **NICE** (remote dep); sharpshooter = **SKIP** (niche).

## F2. Skills system
**What**: File-backed capability packs (`<root>/skills/<name>/SKILL.md`, non-recursive) exposed as name+description metadata in system prompt, on-demand via `read skill://...`, optional `/skill:<name>` commands.
**Key semantics** (omp://docs/skills.md):
- Frontmatter: `name?`, `description?`, `globs?`, `alwaysApply?`, `hide?`, `disableModelInvocation?` (kebab-case normalized); unknown keys preserved. `description` required for native/custom-dir discovery.
- Discovery = 3 passes: capability providers (precedence native 100, plugins 90, claude 80, claude-plugins/agents/codex 70, opencode 55, github 30, omp-managed 5 — dedup by name, first wins), customDirectories (`*/SKILL.md` non-recursive; override same-named provider skills; first-wins among customs), managed (auto-learn, `~/.omp/agent/managed-skills`) dead-last. realpath dedup + collision warnings.
- Filtering: source toggles (enableCodexUser, enableClaudeProject, …), `disabledExtensions: skill:<name>`, `ignoredSkills`/`includeSkills` globs, `skills.enabled: false` kill switch. `.agent[s]/skills` is the canonical native location with its own toggles.
- `hide: true` hides from prompt list but skill stays reachable via `skill://name` and command.
- `skill://<name>[/<rel>]` protocol: exact name, URL-decoded, rejects absolute/`..`/escape outside baseDir, no fallback search, explicit not-found error.
- `/skill:<name>` (opt-in `skills.enableSkillCommands`): embedded whitespace-delimited token in prose supported (not when draft starts with another slash command / bash-py sigil); strips frontmatter; wraps body with name + `[Skill directory: <baseDir>]` + relative-path resolution instructions + `User: <args>`; delivery queue follows submission keybinding (Enter=steer, Ctrl+Enter=followUp — identical to free-text streaming routing). Two invocation prompt templates: user-invoked vs autoloaded (subagent `autoloadSkills` frontmatter must NOT claim user invocation).
- Managed skills: name `[a-z0-9][a-z0-9-]{0,63}`, description sanitized one-line, 64KB cap, never override authored skills.
- AGENTS.md discovery walks ancestor dirs with home/repo-root boundary rules — separate subsystem (covered by session scouts).
**Surface**: `skills.enabled`, `skills.customDirectories`, `skills.enableSkillCommands`, `ignoredSkills`/`includeSkills`, provider toggles, `/skill:<name> [args]`.
**Go port**: Pure stdlib — filepath walk, YAML frontmatter parsing, glob matching, text templates. **Parity**: native dirs + custom dirs + managed + skill:// + /skill: commands = **CORE** (cheap, high value). Marketplace/foreign providers (claude/codex/opencode/github/plugins) = **NICE/SKIP** (v2).

## F3. Memory tool family — learn / recall / retain / reflect / memory_edit
**What**: Five model tools gated by backend + autolearn (omp://docs/tools/{learn,recall,retain,reflect,memory_edit}.md).
**Key semantics**:
- Availability: `recall|retain|reflect` iff backend ∈ {hindsight, mnemopi}; `memory_edit` iff mnemopi; `learn` iff `autolearn.enabled` && backend ∈ {hindsight, mnemopi, local}. All `approval=read`, `strict=true`, discoverable loadMode (in xdev-style sessions discoverables presented as `xd://recall`; explicit request = top-level). Subagents don't auto-receive but can request explicitly.
- `learn(memory, context?, skill?{action:create|update,name,description,body})`: stores lesson FIRST (mnemopi rememberScoped importance 0.8 / local learned.md / hindsight queue), then optional managed-skill create/update; authored-name conflict on create → isError with `shadowed:true` after lesson stored; `create` fails if file exists, `update` if absent; skill-write failure rethrown as partial outcome. Local lessons: newest-first, deduped by normalized line, secret-redacted, ≤100 entries, content ≤2000 chars, context ≤400; injected starting next session (no prompt-cache prefix mutation). Unlike `manage_skill`, learn does NOT refresh active session skill list.
- `recall(query)`: single-shot bullet list; mnemopi format `- content (id: X) [source] (date) c:score` (500-char preview, trailing `…`); hindsight `- text [type] (timestamp)`; no matches → "No relevant memories found." + `useless=true`. Scoped recall merges project+global banks, dedups, caps recallLimit=8. Explicit tool does NOT update the auto-recall prompt block.
- `retain(items[{content,context?}])`: hindsight = queued batch (flush at 16 items or 5s debounce, async retainBatch, failure → session warning notice, model not told); mnemopi = sync SQLite write (importance 0.75, fact, extract:true; failures swallowed). Response = count, not per-item receipt.
- `reflect(query, context?)`: hindsight = remote POST /reflect (server synthesis, budget mid, timeout 120s, best-effort ensureBankExists with reflect/retain missions); mnemopi = local recall + "Based on recalled memories:" formatting only — no synthesis.
- `memory_edit(op=update|forget|invalidate, id, content?, importance?, replacement_id?)`: update/forget = working-memory rows only (episodic → not_found); invalidate works on episodic too; fact rows read-only (`not_editable`); importance clamped 0..1; update requires content or importance; statuses not_found/not_editable are normal results not errors; backend searches retain→recall→global banks in order.
**Go port**: One Go interface `MemoryBackend { Recall, Retain, Reflect, Edit?, SaveLesson? }`; tool JSON schemas trivial. Subtle bits: preview-truncation marker + mandatory `memory://<id>` full-row read before update, `useless=true` flag, queued-vs-sync write semantics.
**Parity**: `learn` + local learned.md = **CORE**; recall/retain/reflect over a local-FTS backend = **NICE**; memory_edit = **NICE**.

## F4. Theme system (user explicitly named theme/color)
**What**: JSON theme system driving every color surface: TUI tokens, markdown adapters, select-list/editor/settings-list adapters, symbol presets (unicode|nerd|ascii), syntax-highlight colors, status-line segment colors (omp://docs/theme.md).
**Key semantics**:
- JSON shape: `name` (req), `colors` (req — **all ~66 tokens required** except optional `thinkingMax`→falls back to `thinkingXhigh`), `vars` (recursively resolved; error on missing/circular), `export` (opt: pageBg/cardBg/infoBg), `symbols` (opt: preset, per-SymbolKey overrides, `spinnerFrames` string[] or {status,activity}).
- Color values: hex `#RRGGBB`, 256-index, var ref, `""` = terminal default (`\x1b[39m`/`\x1b[49m`).
- Token groups (66): core text/borders 11 (accent, border, borderAccent, borderMuted, success, error, warning, muted, dim, text, thinkingText); backgrounds 7 (selectedBg, userMessageBg, customMessageBg, toolPendingBg, toolSuccessBg, toolErrorBg, statusLineBg); message/tool text 5; markdown 10; diff+syntax 12; thinking-mode borders 8+1 (off…max, bashMode, pythonMode); status-line 13 (sep, model, path, gitClean, gitDirty, context, spend, staged, dirty, untracked, output, cost, subagents).
- Box-drawing: `boxRound.*` corners/edges restyle all outlined chrome (tool frames, overlays, code fences, editor, welcome banner); `boxSharp` tees/crosses restyle junctions everywhere; `boxSharp` corners affect markdown tables only (tables stay fully sharp).
- Sources: built-ins (dark.json, light.json, defaults/*.json) take precedence over custom `<dir>/<name>.json`; custom dir `~/.omp/agent/themes` ($PI_CODING_AGENT_DIR override). Load pipeline: read→parse→validate schema (grouped missing-token errors, JSON-path errors)→resolve vars→convert to ANSI by capability.
- Color mode detection: COLORTERM=truecolor|24bit or WT_SESSION → truecolor; TERM dumb/linux/empty → 256; else truecolor.
- Auto dark/light slot: OSC 11 bg luminance → COLORFGBG index (<8 dark) → macOS fallback → dark. Defaults: theme.dark="titanium", theme.light="light", symbolPreset="unicode", colorBlindMode=false. `colorBlindMode` HSV-shifts only `toolDiffAdded` (hex only).
- **Live reload**: watcher on current custom theme file only (built-ins unwatched and win name collisions); debounced reload; errors/temporary absence keep last-good theme; no delete/rename fallback. `setTheme` failure → fallback dark; `previewTheme` = non-persisted temporary apply (settings live preview, restore on cancel).
- Persisted keys: theme.dark, theme.light, symbolPreset, colorBlindMode; legacy flat `theme:` migrated by luminance. Symbol precedence: settings override > theme preset > unicode.
**Go port**: encoding/json + token→ANSI map (raw ANSI or lipgloss). The 66-token list is fully enumerable — enforce completeness at load (grouped error). Live reload via polling (2s debounce) — no fsnotify dep needed. **CORE** (user asked; bounded, high polish, low effort).

## F5. TUI chrome beyond the frame plan — HUD, overlays, dialogs, editor shapes
**What**: Two-layer TUI: differential rendering engine (focus, overlays, cursor, diff) + integration layer mounting extension/custom-tool UI (omp://docs/tui.md, tui-core-renderer.md).
**Key semantics**:
- Component contract: `render(width) → []string` — return the SAME array ref when unchanged (reference-equality memoization; mutating components must implement RenderStablePrefix); optional `handleInput`, `invalidate`, `dispose`, `setIgnoreTight`; `Focusable` is separate; cursor via CURSOR_MARKER emitted in rendered text, hardware cursor positioned by TUI.
- Terminal safety: `visibleWidth()` (ANSI-aware UAX#11), `truncateToWidth`, `wrapTextWithAnsi`, `replaceTabs`; over-wide lines clamped; render hot path never throws on cosmetic width mismatch. ANSI state normalized at row boundaries.
- `ctx.ui.custom<T>(factory, {overlay?})`: interactive-only (guard `hasUI`; headless no-op; RPC unsupported). Non-overlay replaces editor area; overlay = bottom-center full-width via TUI.showOverlay. Controller saves editor text, focuses component; `done(result)` mandatory exactly once → dispose → unmount → restore editor+text+focus. Overlays are viewport-local: composite over viewport, never become history; open/close repaints viewport only.
- Frame plan (likely already in PRD): TerminalFrameProvider → HistoryBatch {id, rows, append|replay} + viewport; exactly-once write + monotonic id ack handshake; app decides finality; overlays never in history. Resize modes rebuild (coding-agent default) / append / preserve via env `PI_TUI_RESIZE_SCROLLBACK`; destructive reset only on explicit gesture.
- Keybindings: `matchesKey(data, "app.interrupt")` action-id matching via injected KeybindingsManager; key-release events filtered unless `wantsKeyRelease=true`.
- Custom tool renderers: `renderCall(args, {expanded,isPartial,spinnerFrame}, theme)` / `renderResult(result, options, theme, args?)` mounted by ToolExecutionComponent.
- Inline images: kitty transmit-once place-many; ImageBudget LRU demotion deletes pixels by id and repaints affected viewport rows with height-preserving text fallback (never replays history, never retransmits base64).
- HUD/status line: themed segments (model, path, git clean/dirty/staged/untracked, context, spend, cost, subagents…) via the 13 `statusLine*` tokens (F4); spinner frames theme-overridable (`status` ~12.5fps loaders/tool indicators vs `activity`).
- Scope note: my assigned docs did not include dedicated HUD/dialog/editor-shape docs; the Component/custom contract + theme token table above are the port-relevant specs. Agent Hub (live subagent roster) borrows the alternate screen for its transcript viewer then restores on close — full-screen surfaces exist outside ctx.ui.custom.
**Go port**: Component interface maps 1:1 to a Go interface with reference-identity memoization. ANSI-aware width = port one width function (rune width table; golang.org/x/text/width). Overlay/done/restore lifecycle = small state machine. **Parity**: status-line/spinner theming = **CORE** (daily-driver chrome); Component/custom-UI contract = **NICE** until extensions exist (TUI core itself already in PRD); kitty images = **SKIP**.
